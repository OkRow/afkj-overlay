# AFKJ Overlay v0.1 — оверлей для AFK Journey

Плашка поверх игры: на экране подготовки к бою с боссом (Царство снов, «Владыка великанов») показывает босса, сложность, теги игры, описание и рекомендуемых героев. Работает только чтением лог-файла игры с диска: в память игры и сетевой трафик не лезет.

> ⚠️ Рекомендации сейчас **тестовые** (помечены «ПРИМЕР — тестовые данные»). Настоящие составы добавим в `data/manual_recs.json`.

## Установка (один раз)
1. Установите **Python 3.12**: https://www.python.org/downloads/ — в установщике обязательно отметьте **«Add python.exe to PATH»**.
2. Распакуйте архив в любую папку (например `D:\AFKJ_Overlay`).
3. Дважды щёлкните **install.bat** и дождитесь «Готово» (2–5 минут, качается PySide6).

## Проверка без игры
- Запустите **demo.bat** — слева сверху появится плашка с Новиком, через ~12 с она свернётся в полоску «Бой идёт…», ещё через ~4 с покажет результат.
- Плашку можно перетаскивать мышью, позиция запоминается. **F8** — показать/скрыть. Значок «A» в трее (возле часов): Показать/Скрыть, Тест (Новик), Открыть папку, Выход.

## Работа с игрой
1. Запустите **run.bat** (окно консоли не открывается; появится маленькая плашка «Ожидание подготовки к бою…» и значок в трее).
2. В игре откройте подготовку к бою с боссом Царства снов — плашка обновится за 1–2 секунды.
3. Игра должна быть в **оконном или безрамочном** режиме — поверх эксклюзивного полноэкранного оверлей не виден.

Если плашка не реагирует: запустите **console.bat** — там видно, нашлась ли папка логов и какие события приходят. Путь к логам можно указать вручную в `config.json`, поле `log_dir`, например:
`"log_dir": "%USERPROFILE%\.limpc\<id>\alilog"`

## Файлы
- `config.json` — настройки (появляется после первого запуска): папка логов, горячая клавиша, прозрачность, позиция.
- `data/manual_recs.json` — ваши/гайдовые составы по боссам (ключ — номер босса, например `3016` = Новик).
- `data/roster.json` — ваши герои; дополняется автоматически из ваших составов (`userdata/roster_auto.json`).
- `userdata/afkj.db` — база ваших боёв (SQLite).
- `run_debug.bat` — запуск оверлея с консолью для просмотра ошибок.

## Доступ к логу, пока игра запущена

Игра открывает `log-client-ev*.dat_000` с share mode 0 (эксклюзивно). Обычный `open`,
CreateFileW с любыми FILE_SHARE и даже SeBackupPrivilege дают ошибку 32 (SHARING_VIOLATION).
Проводник тоже не копирует; TeraCopy иногда обходит это.

Оверлей пробует способы **по порядку** и запоминает первый сработавший. Изменение файла
детектируется дёшево через `os.stat` (mtime/size) — открывать файл для проверки не нужно.

1. `python` / `share_all` / `read_data` / `sync_read` — обычные CreateFileW (на случай других сборок).
2. **`raw_ntfs`** (нужен администратор) — открывает файл только с `FILE_READ_ATTRIBUTES`
   (это обычно проходит при share mode 0), берёт кластерные экстенты через
   `FSCTL_GET_RETRIEVAL_POINTERS`, читает их напрямую с тома `\\.\C:` без буферизации.
   Если файл резидентный в MFT — `FSCTL_GET_NTFS_FILE_RECORD` + разбор `$DATA`.
   Сжатые/зашифрованные файлы не поддерживаются. Это быстрый способ (~мс), без теневых копий.
3. **`vss`** (нужен администратор, запасной) — Volume Shadow Copy. Медленно (~5–10 с),
   не чаще одного снимка в 10 секунд; снимок всегда удаляется после копирования.
   Используется в живом режиме только если `raw_ntfs` не сработал.

Если ни один способ не сработал и оверлей **не** от администратора, в плашке будет:
«Нет доступа к логу — запустите run_admin.bat». После закрытия игры обычное чтение снова
работает и бои сохранятся в историю (режим «после сессии»).

**Важно:** `raw_ntfs` читает то, что уже на диске. Если игра держит свежие события в своём
кэше записи и ещё не сбросила их, VSS (видит кэш ОС) может показать больше событий.
`FlushFileBuffers` по чужому дескриптору недоступен — это видно в сравнении diag.

* `diag.bat` — при открытой игре; скопируйте отчёт.
* `run_admin.bat` — оверлей от администратора.
* `run_admin.bat diag` — диагностика с `raw_ntfs` / `backup`.
* `run_admin.bat diag --vss` — то же + теневая копия и сравнение raw vs VSS.



## v0.1.3

* Исправлено открытие тома: было `\\.\C` (ошибка 2 «файл не найден»), стало `\\.\C:`.
* `raw_ntfs` с метками шагов в ошибках (`open_attr` / `open_volume` / …); запасной FileId через каталог.
* VSS: интервал 5 с; trailing-edge — если файл изменился во время снимка или троттлинга, повтор сразу после кулдауна (раньше плашка появлялась только со 2-й попытки).
* Лог каждого чтения в `userdata/overlay.log` (метод, мс, новые события, подготовки).
* Возраст события: `now_utc − event_utc` (UTC+3 не влияет).
